1. WHAT IS MATHEMATICAL SLIDING WINDOW?
===============================================================================

In some sliding window problems, we DO NOT actually perform the operation
mentioned in the problem.

Instead, we ask:

"Can this window become valid after at most k operations?"

We only COUNT the minimum operations required.

If the required operations <= k,
the window is valid.

Otherwise,
shrink the window.

Think of it as:

        "Check feasibility, don't perform the operation."

===============================================================================
2. GENERAL TEMPLATE
===============================================================================

left = 0

for(right = 0 -> n-1){

    // Expand the window

    Update window information

    while(window becomes invalid){

        Remove left element

        left++;
    }

    Update answer
}

===============================================================================
3. MOST IMPORTANT IDEA
===============================================================================

We NEVER modify the array/string.

We only maintain information about the current window.

For example,

String = AABAB

We NEVER convert

AABAB

into

AAAAA

We simply calculate

"How many characters must be changed?"

4. EXAMPLE 1
   Longest Repeating Character Replacement (Leetcode 424)
===============================================================================

Question:

Replace at most k characters.

Find longest substring consisting of only one character.

Window:

A A B A

Frequency

A = 3
B = 1

Window Size = 4

Most Frequent Character = 3

Characters to Replace

4 - 3 = 1

If

k = 1

Then

YES

because only one replacement is needed.

Notice:

We NEVER actually replace B with A.

We simply know that it CAN be replaced.

===============================================================================
Formula
===============================================================================

windowSize - maxFrequency <= k

If true

Window is valid.

Else

Shrink window.

===============================================================================
Code
===============================================================================

class Solution {

    public int characterReplacement(String s, int k) {

        int left = 0;
        int answer = 0;
        int maxFreq = 0;

        int[] count = new int[26];

        for (int right = 0; right < s.length(); right++) {

            count[s.charAt(right) - 'A']++;

            maxFreq = Math.max(maxFreq,
                               count[s.charAt(right) - 'A']);

            while ((right - left + 1) - maxFreq > k) {

                count[s.charAt(left) - 'A']--;

                left++;
            }

            answer = Math.max(answer,
                              right - left + 1);
        }

        return answer;
    }
}

6. HOW TO IDENTIFY THIS PATTERN?
===============================================================================

Whenever the problem says

At most k

At most x

Can change

Can replace

Can flip

Can remove

Can delete

Can modify

STOP.

Ask yourself

"Do I really need to perform the operation?"

OR

"Can I just COUNT how many operations are required?"

Most of the time,

counting is enough.

8. WHY DOES THIS WORK?
===============================================================================

Suppose

Window

A A B A

Instead of changing

B -> A

we calculate

Replacements Needed

= Window Size - Maximum Frequency

If replacements needed <= k

Then this window CAN become

A A A A

So the window is accepted.

13. GOLDEN RULE
===============================================================================

"Don't perform the operation.

Count the minimum operations needed.

If they are within the allowed limit,
keep expanding the window.

Otherwise,
shrink it."

This single idea solves many sliding window interview problems.
